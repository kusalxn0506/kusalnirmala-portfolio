The Challenge

Our university hosted a PechaKucha 20x20 presentation event with 15 speakers. The organizers needed a way for the audience to vote for the best speaker live, immediately after the presentations concluded. The system had to handle a massive spike in traffic (200+ students voting at the exact same moment), prevent double voting, and provide a visually stunning live leaderboard for the projector screen.

Tech Lead monitoring the live Firebase dashboard during the 2-minute voting window.

The Architecture

With only a week to build, I opted for a 100% client-side architecture using Firebase Firestore for real-time synchronization. There was no backend server to maintain or crash under load.

To avoid massive Firebase Storage costs and bandwidth bottlenecks from 200 phones downloading 15 profile pictures simultaneously, I used the Canvas API to compress and encode the speaker photos as Base64 strings directly into the database. This meant the entire application state (including images) could be synced in a single lightweight JSON payload.

Mobile Web App: Fully responsive voting interface with local storage cache to prevent duplicate votes.

The Projector Dashboard

The centerpiece of the system was the Admin Projector UI. I built a separate web app specifically for the auditorium's main screen. It featured a real-time animated leaderboard powered by GSAP.

As votes poured in, the bars dynamically resized and participants swapped ranks smoothly without page refreshes. To maintain suspense and empathy for all speakers, I implemented a custom filter to only show the Top 5 participants on the final standings screen.

The cinematic winner reveal screen showing the Top 5 leaderboard, ensuring a clean UI and maintaining empathy for all participants.

System Architecture & Features

To handle a massive influx of concurrent votes within a strict 2-minute window, the architecture had to be incredibly robust, lightweight, and real-time. Here is a high-level overview of how the system operates:

The system was designed with several specialized facilities to guarantee fairness, performance, and audience engagement:

  • Zero-Server Infrastructure: By fully utilizing Firebase Firestore's real-time capabilities, I eliminated the need for a custom backend server, entirely preventing server bottleneck crashes.
  • Duplicate Vote Prevention: The mobile web app enforces strict one-vote-per-device rules using localized browser caching, ensuring a fair competition for all 15 speakers.
  • Base64 Image Compression: To drastically reduce bandwidth costs and loading times, all 15 speaker profiles (including images) were compressed and encoded into Base64 strings, synced in a single JSON payload.
  • Dynamic Top-5 Filtering: To maintain suspense and prevent lower-ranked participants from feeling discouraged, the real-time leaderboard intelligently slices the data to only ever display the Top 5 contenders.

Under the Hood: The Code

To pull this off without a hitch, I relied on two major technical pillars: Firebase Realtime Listeners and GSAP Flip animations.

Firebase Data Sync

Instead of manual polling, the projector dashboard uses a live Firestore snapshot listener. The moment a vote is cast on any phone, the projector receives the updated payload in milliseconds.

// Listening for live votes in projector.js
onSnapshot(doc(db, "events", "pechakucha_nsbm_2026"), (docSnap) => {
  if (docSnap.exists()) {
    const data = docSnap.data();
    if (data.participants) {
      updateLeaderboard(data.participants);
    }
  }
});
GSAP Flip Animations

To ensure participants swapped places smoothly on the leaderboard without janky DOM jumps, I utilized GSAP's Flip plugin. It calculates the delta between the old and new DOM states and mathematically animates the transition.

// Animating rank changes with GSAP Flip
function updateLeaderboard(participants) {
  const state = Flip.getState(".participant-row");
  
  // Re-sort DOM elements based on new vote counts
  sortDOMNodesByVotes(participants);
  
  // Animate from old state to new state seamlessly
  Flip.from(state, {
    duration: 0.8,
    ease: "power2.out",
    absolute: true,
    stagger: 0.05
  });
}
